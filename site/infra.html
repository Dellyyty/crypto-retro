Infra · architecture

One directory, no build.

The site is plain HTML, CSS and ES modules. There is no bundler, no node_modules in the runtime path, no server. GitHub Pages serves site/ verbatim. Everything else in the repo exists to verify, document, or ship that directory.

Why no build step

  • Debuggable in production. What you `view-source` is what shipped. No sourcemaps, no minified blob to reverse.
  • No supply chain. The runtime dependency set is empty. The font is vendored with its license.
  • Instant cold start. About 60 KB of code and CSS, one 38 KB font, plus a cached snapshot. It boots on 3G.
  • Fork-friendly. Clone, open, edit, push. No toolchain drift, no lockfile conflicts.

The tradeoff: no tree-shaking, no TypeScript, no framework. For a 1,600-line single-view artifact that is the right trade. ES modules are cached individually by the browser, so the parse cost is negligible.

Layout engine

The stage is a fixed 4:3 box scaled to the viewport: width: min(100vw, 133.333dvh), height: min(100dvh, 75vw). Inside, all typography is in em relative to a single root size, and all panel geometry uses percentage grid rows. The result is a pixel-proportional replica of a 640×480 broadcast at any size, with no media-query breakpoints between 320 px and 4K.

On portrait phones the stage becomes full-height and typography is clamped with min(2.9vw, 4.1dvh). Container queries ( cqw/cqh) size the ticker text and icon blocks against the stage rather than the viewport, which keeps proportions correct when the broadcast is embedded in a card.

Rendering model

  • State: one plain object with six keys (markets, global, fearGreed, chain, eth, funding) plus candles. Written only by api.js.
  • Rendering: pure-ish functions of that state, called after every sweep. No virtual DOM, no diffing library; replaceChildren on the small lists, targeted textContent writes on the rest.
  • Screens: all six exist in the DOM; rotation toggles hidden and a CSS clip-path reveal. Hidden screens are not reflowed.
  • Canvases: DPR-aware (min(devicePixelRatio, 2)), redrawn on screen entry and on resize only.

Rotation is a single setInterval at 11 s. Pausing does not destroy the interval — it short-circuits it — so resuming does not reset the phase of the other screens' entry animations.

Screens and keyboard model

Screen transitions are addressable by URL fragment. The controller writes history.replaceState on rotation and listens for hashchange, so rotation never pollutes browser history while a pasted deep link still lands on the right screen. ?direct skips the title card for embeds.

Keyboard handling lives in one delegated keydown listener that skips inputs. There are no custom widgets: the tabs are real buttons with role="tab" and aria-selected, the ticker is an output with aria-live="polite", mute and pause are aria-pressed toggles.

Verification

Three gates, all runnable locally with Node 20+ and no installs:

npm test        # node --test over pure math/format modules
npm run check   # repo invariants: no TODOs, asset refs resolve, no keys
npm start       # http://localhost:8080 with correct MIME types

CI runs test and check on every push, then deploys site/ to Pages only if both pass. There is no staging tier: a broken commit simply fails before deploy.

Cost and limits

  • Hosting: GitHub Pages, free for public repos, HTTPS, global CDN.
  • Bandwidth: ~110 KB first load, ~1 KB per minute thereafter (JSON only).
  • Upstream: all keyless free tiers, chosen so the project survives a fork with zero configuration.
  • There is no server to page anyone about.
